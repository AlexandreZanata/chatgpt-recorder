# YouTube Automation Bot

Local, hidden-workspace pipeline for the **fallem prince** channel. It takes a
batch count, generates topics when needed, produces the article, narration,
metadata and Black Ink Void thumbnail, renders the video, uploads it as a draft,
adds the end-screen recommendation and **schedules** it. It never publishes
immediately and never opens windows in the main desktop workspace.

## One command

```bash
python3 -m tools.ytbot run --count 10
```

The agent can run that command in the background and only intervene if the bot
reports a failure. A successful run ends with `[ytbot] process finished` and the
batch summary. Failures are recorded and the command exits non-zero.

## First-time setup

```bash
python3 -m tools.ytbot setup
```

This copies the cookies and `Local State` from the normal Chrome profile,
installs the capture extension into the bot profile, and starts Xvfb `:99` plus
the hidden Chrome on CDP port `9300`. The main Chrome is not touched.

If the ChatGPT or YouTube Studio session expires, run `setup` again. On this
machine the bot reuses the already signed-in working profile at
`.local/bot/profile` (the same one used for the proof video). Keep that folder;
`setup` uses it automatically. If it is absent, `setup` creates
`.local/ytbot/profile` from the main Chrome cookies and you may need to sign in
once in the hidden browser.

## Catalog and topic queue

```bash
python3 -m tools.ytbot catalog
python3 -m tools.ytbot check "Why We Avoid Silence"
```

- `.local/ytbot/topics.txt`: one topic per line, used first.
- If the queue has fewer topics than `--count`, the bot asks ChatGPT for new
  topics in the channel style and filters them against the 146-video catalog.
- `.local/ytbot/catalog.json` and `catalog.md` are refreshed by `catalog`.

## Exact process

For every topic, the bot runs these stages and records each one:

1. **Topic** chosen from the queue or generated by ChatGPT.
2. **Article** in the **Simple Deep Dive** GPT using the channel's header prompt.
   The text is cleaned, dashes are removed, and `article.md` + `article.txt` are saved.
3. **Narration** by clicking Read aloud and capturing the AAC/WebM through the
   extension. The conversation URL is recorded so a retry can resume audio.
4. **Metadata** in a new ChatGPT tab with the article attached. The output is
   parsed into title, description, hashtags and tags.
5. **Thumbnail** in a new ChatGPT tab with the article attached and the Black Ink
   Void prompt. The generated image is saved as `thumbnail.png`.
6. **Render** with the existing engine: 1920x1080 / 30 fps, Fallem Prince
   background, no music, quick outro (+5s), synchronized subtitles, 200%
   narration volume.
7. **Upload** to YouTube Studio as a draft with:
   - the first title option, with no em/en dashes
   - the description exactly in the channel pattern, including its hashtags and
     the `TAGS:` line
   - the tags in the tags field (max 425 characters for safety)
   - the custom thumbnail
   - "Não é conteúdo para crianças"
8. **End screen** on the draft edit page: adds the Subscribe element and a Video
   element set to **Melhor para o espectador** (YouTube chooses the best video).
9. **Schedule** on the visibility tab, never publish now:
   - 2 videos per day: **00:00** and **12:00** (12 hours apart)
   - if one slot already has a scheduled video, use the missing slot
   - if both are taken, move to the next day
   - existing slots are read from YouTube Studio's `list_creator_videos` data
   - starts at least 60 minutes in the future
10. **Records** are appended to:
    - `.local/ytbot/records/records.jsonl` (every event)
    - `.local/ytbot/runs/<slug>/record.json` (per-video timeline)
    - `.local/ytbot/records/RECORDS.md` (summary table)

## Output per topic

`.local/ytbot/runs/<slug>/` contains:

| File | Meaning |
|---|---|
| `topic.txt` | exact topic |
| `article.md`, `article.txt` | generated article |
| `narration.aac` / `.webm` | captured Read aloud audio |
| `narration.ass` | synchronized subtitles |
| `metadata.txt`, `metadata.json` | raw and parsed metadata |
| `thumbnail.png` | Black Ink Void thumbnail |
| `video.mp4` | final 16:9 video |
| `upload.json` | video id, public URL, scheduled slot |
| `record.json` | full stage timeline |

## Rules enforced by code

- No em dash (`—`) or en dash (`–`) in titles, descriptions, tags, topics or
  article text. They are replaced with a colon (titles) or comma (body).
- Description follows the existing channel format: paragraphs, hashtags line,
  then the `TAGS:` line.
- Tags are lowercase where required and limited to the YouTube character budget.
- Audience is always "not made for kids".
- Visibility is always **scheduled**, never public at upload time.
- End screen always includes the Best for viewer recommendation.
- The bot is resumable: existing article/audio/metadata/thumbnail/video/upload
  files are reused, so a failed stage does not repeat completed work.

## Notes

- If an upload lands on the Google account chooser, the bot profile session
  expired. Sign in once in `.local/bot/profile`, or finish the uploads with the
  already signed-in main Chrome profile launched on Xvfb (the bot cannot use that
  profile while the normal Chrome is open).
- YouTube Studio data can lag a few seconds after scheduling; the bot confirms
  the schedule from the edit page/upload dialog and retries.
- The pipeline is sequential to keep the account and audio capture reliable.
  A 10-video batch can take several hours; run it detached and inspect the log.
- The ChatGPT profile is separate from the normal Chrome. The main workspace is
  not used and no window appears on the visible desktop.
- Upload and scheduling use a locally launched Playwright Chrome with the same
  profile because YouTube requires a real browser session for large files.
- The previously published proof video was an exception from before the
  scheduling rule. Every new video follows the scheduled workflow.
